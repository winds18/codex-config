# Codex 跨项目、跨任务协作能力研究

核实日期：2026-09-08。审查基线：`c730006991bfb65ba872375f1131cd0b20ee6185`。本机实测 `codex-cli 0.153.4`；官方手册本轮重新获取并校验。本文保留研究推导与实施依据；用户要求继续严谨优化后，相关规则已在仓库真源落地，实施核验记录见文末。

## 判断

优先补齐“定位既有任务 → 对齐契约和版本 → 在已授权范围同步增量 → 等待有效结果 → 联合验收”的流程。当前规范已经具备有条件的子代理并行、单写入负责人、架构/契约先行和实际证据验收，不需要增加固定角色编队或全量任务台账。

以下区分三种依据：官方文档描述的产品能力、当前会话实际提供的工具契约，以及据此提出的工程建议。当前支持不代表近期刚发布；工具已提供也不等于本轮实际调用验证过跨任务执行。

### 多目录项目的关键边界

官方明确：新任务从主目录启动，Git 默认操作和 AGENTS、技能、config 的自动发现基于主目录；次目录仍可读写，但不会自动发现其中这些项目配置。worktree/PR 操作针对主仓库，其他目录继续挂载。[项目文档](https://learn.chatgpt.com/docs/projects)

据此，工程规则应要求：修改次仓前主动读取其适用规则；每个 Git 操作明确工作目录；并行计划列出所有实际写入目录。**不能从“主仓创建了 worktree”推断次仓也被隔离**，需要逐仓核对。外部数据库、端口、服务、缓存和输出目录继续适用现有资源归属规则。

环境准备优先复用项目脚本和锁定依赖。`.worktreeinclude` 可复制匹配的忽略文件，但其适用范围是本地受管 worktree，不能推定远程或自行创建的 Git worktree 一样处理；必要配置按实际环境核对，避免复制无关本地状态。[Worktrees](https://learn.chatgpt.com/docs/environments/git-worktrees)

## 当前会话工具边界

依据是本轮会话公开提供的工具说明，未为研究实际创建、续接、迁移其他用户任务或建立自动化。不把桌面工具名固化到全局规则；具体操作说明放客户端适配层，并在调用时重新核对。

| 操作 | 当前工具 | 需要保留的语义 |
| --- | --- | --- |
| 定位与读取 | `list_projects`、`list_threads`、`read_thread` | 用返回的项目/任务 ID 与宿主信息定位，名称只辅助选择；摘要是检索线索，必要事实再读，避免全量扫历史 |
| 续接已有任务 | `send_message_to_thread` | 会产生用户可见提示并触发/引导执行；确认目标和已有统筹授权，传递增量，不重复派发相同工作 |
| 等待已有任务 | `wait_threads` | 支持游标、有限目标批次、完成/需关注事件和即时快照；当前上限为 8 个目标，按实际契约使用，不把上限当推荐编队 |
| 创建独立任务 | `create_thread` | 仅在用户明确要求新任务时；先核对项目，Git 默认 worktree；保留用户明确的目录和起点要求。异步 `clientThreadId` 不是可供其他任务工具使用的就绪 `threadId` |
| 分叉 | `fork_thread` | 是独立任务分支；只复制已完成历史，运行中的本轮及未完成回答不会复制。先满足相应请求，分叉后明确新目标与写入范围 |
| 环境交接 | `handoff_thread`、`get_handoff_status` | 移动其他任务及 Git 状态，会中断其运行；本任务不能通过该工具移动自己，当前工具不支持 cloud handoff。返回 operationId 后确认完成；本会话仅提供 Local 目标 |
| 后续跟进 | `automation_update` | 同任务持续跟进默认 heartbeat；独立任务按相应请求创建。现有任务先查询更新，不重复建立；通知偏好用专用字段保存 |

公开定时文档还描述了多项目独立运行，以及网页/移动端的事件触发；**当前桌面工具公开的 cron 创建结构仅有单个 projectId，本轮没有事件触发创建工具**。不能把产品其他界面的能力直接当作本会话可执行接口。[定时任务](https://learn.chatgpt.com/docs/automations)

## 从能力推导到规范

### 全局只补一条原则

> 跨项目或跨任务协作先定位已有成果、负责人和依赖，再按授权同步必要增量；逐仓核对规则、版本与写入隔离，由明确负责人完成联合验收。内部并行优先子代理，独立任务的创建继续依用户请求执行。

### 详细流程集中维护

现有[并行执行与交接](../../skills/autonomous-project-execution/references/autonomous-execution-workflow.md)新增按需小节，保留以下推导要点；实际规范在该参考中凝练维护：

1. **选择协作范围**：普通独立子工作留在当前任务；已有相关用户任务先定位、读取并核对实际状态，在已有授权内续接。只有需要独立任务且用户已有对应请求时创建或分叉；总控职责由当前主任务或已有协调任务承担。
2. **固定依赖基线**：跨仓工作包按需标明仓库/目录、任务 ID、写入负责人、branch/ref 与被测 SHA 或包版本、契约权威来源、生产者/消费者关系、验收命令。不要只写各仓“最新版”。复用现有 issue/spec/计划，不另建完整动态台账。
3. **先定契约再分发**：明确接口、失败语义和兼容要求后，让各实现方并行；契约变化由其负责人维护，向受影响任务发送“变化、影响、新基线、需执行动作”，避免反复转发全历史。
4. **按资源隔离写入**：核对每个仓库和次目录的真实检出，明确共享数据库、端口、缓存及输出目录。跨任务改派同样先确认旧执行者停止，超时或不可见不等于停止。
5. **按事件协调**：通过状态和增量结果确认进展；发送回执不当完成，某任务完成不当联合验收。等待时继续无依赖工作；收到同一结果不重复派发或重做。有相关变化或新证据暴露未决风险时，重开受影响验证。
6. **统一集成验收**：各仓负责人交付可定位产物和对应验证；总控针对参与版本组合验证真实链路。单仓 CI 绿或历史任务摘要不能证明整体完成。需要发布时再按既有授权确认兼容窗口与发布顺序。
7. **有界持续跟进**：当前运行结果用等待工具；明确需要稍后续办时使用已授权的会话自动化，写清完成、失败和需用户决定的处理及终止条件。完成后按既有授权收口跟进，清理自有临时产物；不默认关闭用户其他任务。

## 保留和暂缓

- 保留现有子代理触发规则。当前官方本地 Codex 仍要求用户直接请求或适用 AGENTS/技能要求才委派；本仓库的有收益并行约定已满足条件。角色和并发容量以实际运行时为准。[Subagents](https://learn.chatgpt.com/docs/agent-configuration/subagents)
- 现有项目配置模板已经使用 `max_concurrent_threads_per_session`，不必为旧别名再做迁移。无需增加固定代理数、所有任务使用 Ultra、强制新开对话或固定轮询周期。
- Goal 继续只响应明确请求；长任务先有结果、边界和验收，不把所有复杂任务改成后台自动化。[长期工作](https://learn.chatgpt.com/docs/long-running-work)
- 记忆、Record & Replay、插件适合稳定且重复的场景，可作为后续专项；先有可重复的流程再封装。CLI/测试脚本已有可靠入口时继续复用。[Record & Replay](https://learn.chatgpt.com/docs/extend/record-and-replay)
- 0.153.0 的新上下文管理仍为实验项，不能写成必需工具或由安装器默认开启。本轮当前工具也未提供 `new_context`。Fast mode、模型和额度设置按实际偏好处理，不作为规范升级的隐含变更。[变更日志](https://learn.chatgpt.com/docs/changelog)

## 后续验收设计

后续可在真实项目固定模型和类似任务对比旧/新流程，不以文本缩短或代理增多宣称提效。

| 场景 | 应观察的行为 |
| --- | --- |
| 同一需求已有两条相关任务 | 找到既有成果与执行者；不重做、不无请求新建任务；只同步必要变化 |
| 前端、API、SDK 三仓实现同一接口 | 契约来源和参与版本明确；实现并行，最后验证同一版本组合 |
| 多目录项目只给主仓建 worktree | 发现次仓并未被证明隔离；核对其规则和负责人后才写入 |
| 一条任务超时、另一条仍在写共享资源 | 不把超时当停止，不产生两个活跃写入负责人 |
| 向新建任务收到异步回执或重复状态 | 等到真实就绪/完成并消费增量，不误用 ID、不重复派发 |
| 等待 CI 或必要的产品回答 | 当前结果用等待、稍后续办按请求自动化；无依赖工作继续，未获必需答案不执行依赖部分 |

记录整体完成率、关键路径耗时、重复读取/派发、冲突返工、实际追问、重复测试和可获取用量。还应观察取证、等待和清理是否增加了净收益；本轮完成下述离线行为试用，没有实际开展跨仓开发对照试验。

### 多端职责分组增补

用户进一步建议按前端、后端等对话组组织开发。以 `235e7db` 为本次增补基线，在并行参考增加“按职责组织多端任务”：持续职责保留上下文，每个功能跨端协作并联合验收，每条任务仍有阶段成果，短期独立工作用子代理。其他五个文件仅补路由、可选交接信息或客户端说明，全局 AGENTS、角色、安装及权限配置未改。

推导边界：官方项目文档支持用相关任务组织不同成果；本会话工具支持侧栏分类并明确用户任务平级。因此，职责组织作为工程约定，侧栏分类作为可选导航；不能据此推定自动共享上下文、层级从属或隔离。实际创建任务、移动或重命名仍遵守对应请求和工具契约。[项目文档](https://learn.chatgpt.com/docs/projects)

独立只读复核未发现需要修正的问题。另一个独立代理只读技能及必要参考，完成一次含两类案例的离线行为试用，主任务核对了生成正文：
