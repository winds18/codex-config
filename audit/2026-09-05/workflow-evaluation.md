# 自主开发工作流试用

日期：2026-09-05。目标是检查新规范是否仍会因缺少治理文档、需要交接或子代理不可用而卡住；这是一次小样本行为检查，不是速度基准。

## 输入与约束

主任务建立临时 Python 3.9 标准库项目，提供 README、公开不可变 `Order` 数据类及 1 个原有契约测试。项目没有 spec/plan。独立代理阅读更新后的 `autonomous-project-execution` 技能后负责交付：

- `summary.py`：汇总未取消订单，金额保留 Decimal 精度，按客户名排序。
- `export_csv.py`：按输入顺序导出全部订单，金额两位小数，取消状态 true/false，正确转义 CSV 特殊字符。
- 保留 Order 契约及原有测试；不安装依赖，不联网，不提交或推送。两个模块的文件归属可独立划分。

## 实际行为

独立代理尝试将 CSV 模块分给子代理，同时自己处理汇总模块；运行环境返回代理线程容量上限。代理直接在本地完成剩余模块，没有等待不存在的代理，没有额外追问，也没有为了满足流程生成 spec/plan/bootstrap。

最终新增两个实现文件和两个测试文件，原 Order 与原测试保留。主任务逐文件复核：公共输入契约没有改变，Decimal 汇总保持精度，CSV 使用标准库 writer 处理引号、逗号及换行；保存副本后独立重跑全部测试通过。

## 可复查产物

保存的 [项目副本](workflow-trial/README.md) 包含七个文件：README、Order、两个实现、三个测试文件。命令：

```bash
cd audit/2026-09-05/workflow-trial
python3 -B -m unittest discover -s tests -v
```

结果：**9/9 通过**。覆盖汇总取消过滤、排序、Decimal 精度、单次迭代器、空输入；CSV 行顺序、舍入显示、布尔格式及引号/逗号/换行转义；保留原契约检查。

## 能证明与不能证明

该样本支持“无文档门槛仍能交付”“容量不足会继续执行”“实现后有实际验收”的判断。代理确实选择了并行拆分，但容量限制使本样本没有产生实际子代理并发，所以不能用它证明并行速度提升。

主任务本次仓库审计采用了安全脚本、安装器和前端技能的并行文件归属，随后进行跨负责人复核并集成；这验证协作过程可运行，但同样不是控制变量后的速度实验。复杂业务项目、长任务压缩、权限阻塞、自动化和全部技能触发仍需另行抽样。没有虚构耗时对照或固定提速倍数。
