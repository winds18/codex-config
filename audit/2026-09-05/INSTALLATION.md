## 入口与职责

`bash install.sh --apply` 串起源码预检、事务安装和安装后诊断。根脚本处理运行环境和软连接路径；`scripts/setup-codex-config.py` 负责编排；`scripts/manage-codex-config.py` 继续负责清单、备份、冲突、恢复与文件诊断。共享命令行和 doctor 接口确定后，编排/文档与核心诊断/恢复测试分工实现，最后由主任务集成，并由独立代理复核。

默认仅预览；`check`、`doctor` 只读；`uninstall`、`recover` 复用事务层且不受规范文本损坏影响。自定义配置根安装 `codex-config.sh`，后续运行自动绑定所在根。重复安装应用当前源码，保留原备份和外来配置。

源码预检只读检查来源完整性、角色与技能结构、文档引用、Python/Bash 语法和模板本地依赖；不执行全套回归、hook 或上游模板代码。完整源码压缩包无需 Git、rg、Codex CLI 即可安装。Git hooks 保持独立选装，不把两种事务拼成无法统一回滚的隐式操作。

doctor 区分错误和环境提示：待恢复事务、文件漂移、断链和备份损坏失败；缺少 CLI、override 或重复技能提示不伪装成文件损坏。安装后诊断失败时返回非零，明确配置已写入；不输出总体安装成功，也不盲目回滚外部修改。

## 验证

隔离测试覆盖默认零写入、显式预览、重复安装、精确卸载、含空格/引号/中文/美元符号路径、自定义技能根与环境变量、损坏配置/脚本/引用、目录重叠、坏规范下卸载及事务恢复、安装后并发漂移，以及缺少 Git/rg/Codex CLI 的完整源码安装。核心回归同时检查 doctor 的警告/错误与自定义技能目录。

独立代理使用自定义源码与配置目录复核预览、安装、诊断、恢复和卸载；config.toml/auth.json 哨兵保持不变，未写信任状态。主任务补充检查从另一个完整入口安装时，目标来源缺少运行依赖也必须在写入前失败。

全仓 guard 通过 **146 个行为用例**：74 个 hook、22 个敏感信息扫描、31 个配置/Git 恢复、12 个统一安装入口和 7 个模板依赖用例。配置结构与引用、脚本语法、294 个模板文件的 152 个本地引用、工作区清洁检查同时通过。模板保留 1 个预期的坏图片测试 fixture 注记。

本轮修改 7 个已有源码/文档并新增 3 个入口/测试文件；其余 353 个源码文件与前轮摘要一致，其中 294 个上游快照全部保持不变。完整命令输出、运行环境、独立复核范围与本轮文件 SHA-256 见 [验证记录](installation-verification.json)。

## 边界与使用

用户入口见 [README](../../README.md)、[安装说明](../../docs/restore-codex-setup.md) 和 [恢复说明](../../docs/restore-codex-official-state.md)。回归环境为 macOS、Bash 3.2、Python 3.9；未据此宣称 Linux/WSL 或真实客户端已完成验证。入口需要 Bash/Python，不自动下载依赖或源码。无清单的旧整目录安装仍需确认对应原备份；源码和备份都丢失不能自动恢复。

本轮只修改仓库源码；未安装到真实用户配置、未更改实际 Git hooks、未提交或推送。测试临时目录由上下文清理，audit 保留复查证据。

## 发布前复核补充

用户随后授权复核通过后提交并推送。独立规范复核完整阅读 42 个文件，检查 41 处本地引用，没有发现新的实质矛盾。事务层继续用真实文件与子进程退出复现，发现两处先前用例未覆盖的故障：

- 备份是有效 JSON，但文件 data 已损坏为无效 base64；doctor 和卸载仍返回成功，原 AGENTS 被恢复成空文件且备份清单被删除。
- 卸载恢复原技能实体目录时，进程在写完第一个文件后骤停；recover 把自身只写到一半的目录当成外来修改而拒绝继续。

相应补强为恢复前严格验证完整快照及新清单备份摘要，并使用有事务记录的同目录暂存与完整入口替换；保留外部改动的冲突保护。旧清单只能校验已有信息，摘要从升级时的备份建立，不声称能追溯之前是否损坏。最终命令输出、兼容范围和文件摘要记录于 [发布验证](release-verification.json)。前面的 146 用例记录属于补强之前，不替代最终发布验收。

进一步补上孤立备份保护、检查到写入之间的状态复验，以及目录子项格式检查；清理暂存原入口前也核对其内容，防止误删期间出现的外部编辑。独立复核已关闭所报问题。发布前最终全仓 guard 通过 **158 个行为用例**：74 个 hook、22 个敏感信息扫描、43 个配置/Git 恢复、12 个统一入口和 7 个模板依赖用例。安装、恢复和 Git hooks 行为测试均在隔离目录运行；真实推送使用用户指定的专用 SSH 密钥。
