# 并行执行与交接

## 划分工作

主任务按 [软件工程流程](software-engineering-workflow.md) 确定模块边界与共享契约，再分出有收益的独立实现，自己推进关键路径。工作包可用一段话说明：目标、必要输入/当前基线、负责文件与运行资源、共享接口、相关授权及禁止动作、验收方式。

| 情况 | 执行方式 |
| --- | --- |
| 小修或紧密依赖排障 | 主任务直接执行 |
| 独立探索、模块实现或风险复核 | 子代理并行；有证据需求的独立复核可以检查相同代码 |
| 共享 schema、锁文件或公共组件 | 指定负责人稳定契约，依赖方再实现；无关工作继续 |
| 测试共用数据库、端口、缓存或输出目录 | 分配隔离资源；无法隔离的冲突步骤串行 |
| 独立实验或需保护现有 checkout | 使用可用 worktree，并单独处理运行资源；worktree 不隔离外部数据库/服务 |
| 已有相关项目/用户任务 | 按下文统筹，先复用已有成果与负责人，再按授权续接 |
| 用户明确要求独立用户任务 | 按任务工具创建并追踪；内部委派留在当前任务 |

按实际工作与宿主容量选择代理数量；创建失败时使用现有代理或本地继续，不反复等容量。复用已有调查，委派不扩大原授权，重新委派也不能消除已有拒绝。回传聚焦结论、产物/证据定位和限制，原始长日志按需读取。

## 写入与交接

- 一个写入范围只有一个活跃负责人。未经归属确认不改共享文件或资源；发现接口差异给负责人，由其更新并通知受影响方，独立工作继续。
- 需求或约束变化时主任务更新受影响工作包。子代理发现冲突先回报；能依据现有授权解决的技术选择由负责人处理，不机械升级给用户。
- 改派或接管前，确认旧执行者及相关写入进程已经停止；失联、超时或已发送停止请求都不是停止证据。先核对遗留 diff/运行状态，再交接，不能双写抢进度。
- 子代理交付负责文件、行为变化、实际检查及结果、未验证面和遗留进程。主任务检查真实产物，不仅凭成功摘要合入；不覆盖用户或同伴改动。

## 跨项目与既有任务统筹

仅在交付依赖多个仓库、独立项目目录或既有用户任务时使用；普通任务不扫描其他项目和对话。当前主任务可承担统筹职责，无需另外创建总控任务。客户端工具及多目录边界见 [客户端适配](../../../docs/client-compatibility.md#跨项目与任务工具)。

- **定位与复用**：按目标查找相关项目/任务，用真实 ID、宿主和目录确认归属，先读摘要再补必要证据。向既有任务发送内容会启动或引导执行，须核对目标及已有统筹授权；只传新事实、影响、基线和所需动作，不重复派发。创建或分叉独立用户任务继续依相应用户请求。
- **契约与基线**：复用现有工作包或计划，按需补仓库/检出目录、执行任务、写入负责人、branch/ref 与被测 SHA 或包版本、契约权威来源和生产者/消费者关系。契约确定后并行实现，变化同步受影响方；不能只约定各仓“最新版”，也不复制完整动态状态台账。
- **逐仓隔离**：多目录项目不可假定次仓规则已自动加载，也不可假定主仓 worktree 隔离了其他目录。修改前读取各仓适用规则，Git 操作指定相应目录，核对实际检出和外部资源归属。必要环境复用项目 setup/验证入口；仅对缺失的部分补齐。
- **状态与交接**：运行状态优先增量快照、游标或完成事件，区分已派发、已就绪、执行完成和集成通过。异步创建或迁移先确认可用 ID/完成状态；分叉历史不保证含当前未完成工作，环境迁移后重新核对目录、差异和依赖。接管继续遵守停止写入的要求，结果重复或暂时不可见不触发重复执行。
- **联合验收**：各仓保留各自写入负责人，明确一名联合验收负责人。证据绑定参与版本组合和实际环境，验证真实跨仓链路；单仓完成、单仓 CI 绿或历史摘要不足以证明整体交付。只有涉及发布时，才按既有授权处理兼容窗口及发布顺序。

## 验收与收口

证据要能定位到检查命令或操作、相应文件/环境和结果；未变化的局部证据可复用，共享接口或依赖变化后重跑受影响检查。只有需要追踪版本时才记 commit/hash，不为每轮增加表单。

必需工作仍在运行时，用有界等待/完成事件追踪，自己继续独立工作。结束前处理无关代理和写入进程；用户要求持续运行的服务或自动化可保留，并明确用途与状态。目标或必要验收未完成时说明实际阻塞，不能报告完成。

确需稍后跟进且已有相应请求时，使用可用自动化并优先续接同任务；先查已有安排再更新，明确可执行动作、通知和终止条件。运行结果等待、定时跟进和原生 Goal 按各自用途选择，不以持续交付为由自动创建后两者。异步澄清工具可用时尽早提出必要问题，同时继续无依赖工作；未获必需答案前不执行依赖部分。

暂停或压缩前只保存必要续接信息：当前约束、完成/剩余、写入归属与活跃资源、有效验证及阻塞。恢复时核实变化，不重做全量调查。
