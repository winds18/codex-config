# 并行执行与交接

## 划分工作

Codex 自主开发与外部 Agent 协作两种模式并存，可按工作包组合或随任务调整，不以项目大小划硬界，也不要求用户每次指定模式。两者均按 [软件工程流程](software-engineering-workflow.md) 定义目标、模块边界与共享契约，由 Codex 保留关键取舍和最终验收责任；调查、实验及方案比较可委派，核心结论依据证据独立判断。工作包可用一段话说明：目标、必要输入/当前基线、负责文件与运行资源、共享接口、相关授权及禁止动作、验收方式。

需要启动服务、构建、浏览器测试或分配大量存储时，工作包补充可复用实例、资源额度、停止/清理方式与回收时点，确保子代理收到，不假设其已加载完整技能。嵌套委派共用根任务额度，不能各自按全机容量启动；资源细则见软件工程流程，不为只读小任务建立台账。

内置子代理按 [角色与模型选择](agent-role-matrix.md) 确定职责、模型及推理强度；外部 Agent 按实际能力及派发、上下文传递、等待、复核与返工的总成本选择，优先胜任的低成本执行者，不以 token 单价替代整体收益。允许嵌套委派时传递能力要求与预算，不在角色文件固定型号。两类执行者使用同一工作包和交接约定，不假定跨执行环境自动继承规则或权限，仅传必要上下文。

| 情况 | 执行方式 |
| --- | --- |
| 自主推进更直接、协作收益有限 | Codex 自主开发，按需委派内置子代理；不为协作形式接入外部 Agent |
| 执行投入较大、工作可独立交付且外部协作有净收益 | Codex 主编排已授权且可用的外部 Agent，承接适合其能力的执行工作；可结合内置子代理，不限定任务类别或要求全部外包 |
| 外部能力缺失、接入成本过高或执行者不胜任 | 继续 Codex 自主开发与内置协作，不停工等接入、不自动安装；能力不匹配时及时改派或接管 |
| 小修或紧密依赖排障 | 主任务直接执行 |
| 独立探索、模块实现或风险复核 | 子代理并行；有证据需求的独立复核可以检查相同代码 |
| 已有原生或 PR 审查结果 | 按 [变更审查](software-engineering-workflow.md#变更审查) 复用有效结论；子代理只补明确缺口或专项复核，不重复派发同范围全量审查 |
| 共享 schema、锁文件或公共组件 | 指定负责人稳定契约，依赖方再实现；无关工作继续 |
| 测试共用数据库、端口、缓存或输出目录 | 分配隔离资源；无法隔离的冲突步骤串行 |
| 独立实验、冲突写入或需保护现有 checkout | 优先考虑受管 worktree；创建与集成成本高于收益时串行，不为小改固定建树；外部资源仍单独隔离 |
| 已有相关项目/用户任务 | 按下文统筹，先复用已有成果与负责人，再按授权续接 |
| 用户明确要求独立用户任务 | 按任务工具创建并追踪；内部委派留在当前任务 |

按实际工作与执行环境容量选择代理数量；创建失败时使用现有代理或由主任务继续，不反复等容量。复用已有调查，委派不扩大原授权，重新委派也不能消除已有拒绝。回传聚焦结论、产物/证据定位和限制，原始长日志按需读取。

协作时将适合执行者能力、可独立验收的工作优先委派，按完整成果拆包，不以固定任务清单限制范围，也不逐函数派发或逐项审批局部选择。Codex 解决关键不确定性、推进未委派关键路径并准备集成，不重复执行已分配工作或只转发消息；立即依赖且自行完成更快的工作直接处理。只在结果成为依赖时等待，依当前工具契约使用完成事件或有界等待，不以短周期轮询替代独立工作。

## 按职责组织多端任务

前端、后端或其他端具有持续且可独立推进的职责时，可按职责组织已有专责任务，保留各自上下文；小需求仍可由一个负责人贯穿。职责可以长期稳定，每条任务仍须有具体阶段成果与完成条件，不形成“所有前端工作”无限排队的长对话。内部短期工作用子代理，创建独立用户任务继续依相应请求。

| 职责示例（按需采用） | 负责结果 |
| --- | --- |
| 统筹/集成，可由当前主任务承担 | 架构与契约协调、依赖解除、参与版本组合和端到端验收 |
| 前端/客户端 | 本端交互、状态、接口消费及相关测试 |
| 后端/服务 | 本端业务、接口实现、数据行为及相关测试 |
| SDK、移动端、独立复核或运行环境等 | 仅在确有独立交付或复核需求时设立相应职责，避免固定全套团队 |

- **围绕功能交付**：同一需求把可观察验收分到受影响各端，基于同一契约版本并行；不把前端、后端任务列表各自清空当成功能完成。各端负责自己的测试，mock/单端结果是阶段证据，整体依下文联合验收。
- **明确交界**：在既有计划中按需关联职责、实际任务 ID、负责目录及共享契约负责人。共享 schema、SDK/生成代码、锁文件和测试资源继续按具体范围指定单一写入负责人，职责标签不能替代隔离。
- **保持自主**：统筹协调跨端变化，不逐项审批局部技术决定或转发所有消息；相关负责人按授权直接同步必要契约增量。独立工作包可在职责内并行委派，主任务避免重复下派或接管其写入范围。
- **按阶段续接**：复用仍适用的任务和成果。确需独立上下文且已有对应请求时再新建，交接权威契约、版本、有效证据和剩余工作；稳定结论放项目文档，动态状态以工具为准，不依赖长期对话自动共享全部历史。

## 写入与交接

- 同一检出目录或共享运行资源的重叠写入只有一个活跃负责人；隔离 worktree 可同时修改同名文件，须明确集成负责人并解决冲突。未经归属确认不改共享范围；接口差异由负责人协调，独立工作继续。
- 需求或约束变化时主任务更新受影响工作包。普通细节由负责人合理假设并推进；共享契约冲突交主任务协调，只有需用户决定的目标、授权或重大不可恢复影响才提问，不逐级转交常规技术选择。
- 改派或接管前，确认旧执行者及相关写入进程已经停止；失联、超时或已发送停止请求都不是停止证据。先核对遗留 diff/运行状态，再交接，不能双写抢进度。
- 子代理交付负责文件、行为变化、实际检查及结果、未验证面，以及其创建资源的标识、回收检查结果或显式交接。保留服务说明用途、当前状态、停止方式和后续负责人或结束条件；由接收方确认接续责任，不能将遗留资源默认为主任务已接管。主任务核对证据，失联或证据缺失时核实实例归属与存活后处理，不把关闭代理当成资源回收；不覆盖用户或同伴改动。

资源生命周期详细规则统一见 [软件工程流程](software-engineering-workflow.md)。成功、失败、取消或超时都须落实资源回收或交接，只处理归属明确且在授权范围内的任务自有资源，不影响既有共享服务、缓存或持久数据。

## 跨项目与既有任务统筹

仅在交付依赖多个仓库、独立项目目录或既有用户任务时使用；普通任务不扫描其他项目和对话。当前主任务可承担统筹职责，无需另外创建总控任务。客户端工具及多目录边界见 [客户端适配](../../../docs/client-compatibility.md#跨项目与任务工具)。

- **定位与复用**：按目标查找相关项目/任务，用真实 ID、宿主和目录确认归属，先读摘要再补必要证据。向既有任务发送内容会启动或引导执行，须核对目标及已有统筹授权；只传新事实、影响、基线和所需动作，不重复派发。创建或分叉独立用户任务继续依相应用户请求。
- **契约与基线**：复用现有工作包或计划，按需补仓库/检出目录、执行任务、写入负责人、branch/ref 与被测 SHA 或包版本、契约权威来源和生产者/消费者关系。契约确定后并行实现，变化同步受影响方；不能只约定各仓“最新版”，也不复制完整动态状态台账。
- **逐仓隔离**：多目录项目不可假定次仓规则已自动加载，也不可假定主仓 worktree 隔离了其他目录。修改前读取各仓适用规则，Git 操作指定相应目录，核对实际检出和外部资源归属。必要环境复用项目 setup/验证入口；仅对缺失的部分补齐。
- **状态与交接**：运行状态优先增量快照、游标或完成事件，区分已派发、已就绪、执行完成和集成通过。异步创建或迁移先确认可用 ID/完成状态；分叉历史不保证含当前未完成工作，执行环境改变后核对适用规则、目录、差异及依赖。断线或界面关闭不证明工作停止，续接先查实际状态，避免重复执行；接管继续遵守停止写入要求。
- **联合验收**：各仓保留各自写入负责人，明确一名联合验收负责人。证据绑定参与版本组合和实际环境，验证真实跨仓链路；单仓完成、单仓 CI 绿或历史摘要不足以证明整体交付。只有涉及发布时，才按既有授权处理兼容窗口及发布顺序。

## 验收与收口

证据要能定位到检查命令或操作、相应文件/环境和结果；有效证据直接复用，仅因相关变化、具体失败或明确覆盖缺口补验。非阻塞建议在交付时简记，不反复派发审查；需要追踪版本时才记 commit/hash，不为每轮增加表单。

必需工作仍在运行时，用有界等待/完成事件追踪，自己继续独立工作。结束前处理无关代理，并核对各工作包自建资源的回收或交接结果；用户预览等有明确保留需求的服务或自动化可保留，按上述要求交接用途、状态、停止方式和后续负责人或结束条件。目标或必要验收未完成时说明实际阻塞，不能报告完成。

确需稍后跟进且已有相应请求时，使用可用自动化并优先续接同任务；先查已有安排再更新，明确可执行动作、通知和终止条件。运行结果等待、定时跟进和原生 Goal 按各自用途选择，不以持续交付为由自动创建后两者。需要用户决定时可异步澄清，只暂停依赖答案的步骤，其他工作继续。

暂停或压缩前只保存必要续接信息：当前约束、完成/剩余、写入归属与活跃资源、有效验证及阻塞。恢复时核实变化，不重做全量调查。用户纠偏时先判定哪些在途动作或授权已失效，停止受影响部分并传递增量；外部工具结果或代理消息不构成新的用户授权。
