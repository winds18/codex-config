# 关键动效设计与审查

用于新增、调整或审查有意义的组件运动。已有短反馈的小修可直接沿用 motion tokens；复杂手势、转场和持续动画才需要展开完整契约。

## 先明确作用

用一句话说明触发方式、要表达的状态/空间关系和频率。不能说明作用时，先考虑即时反馈或静态表达。无需依赖其他未安装的术语 skill；术语服务于共同理解。

关键动效契约可以是任务记录或组件文档中的一小段：

- 触发与频率：click、focus、drag、route change、scroll、data update。
- 状态与目的：起始/结束/退出，以及反馈、连续性、状态指示或解释。
- 实现：已有工具、动画属性、时长/easing 或 spring、必要的 transform-origin。
- 中断与降级：重复触发、取消/卸载、触控、键盘、reduced motion。
- 证据：在哪些视口/状态验证，仍有什么限制。

## 选择依据

| 判断 | 默认选择与例外 |
| --- | --- |
| 高频工作流 | 即时或短反馈；不要等待完整动画才接受下一次操作 |
| 偶发弹层/转场 | 可用短转场解释空间关系；纯 fade 也是有效方案 |
| 工具 | 优先已有 CSS/WAAPI/动效库；手势和可中断运动再考虑 spring，不为简单 fade 新增库 |
| 属性 | 优先 transform/opacity；高度、颜色、clip-path 等按必要性和实测成本选用 |
| 时长 | 短反馈可从 100–200ms、弹层从 150–300ms 试起；遵循现有 tokens，较长过渡需符合实际用途 |
| 曲线 | 即时反馈通常 ease-out；移动可用 ease-in-out，循环可用 linear；进入/退出方向和项目风格决定最终曲线 |
| 触发锚点 | popover/menu 的运动方向或 origin 应帮助理解与触发源的关系 |
| 悬停 | hover 增强有触控/键盘等价路径，避免触屏粘滞 hover |

这些是起点，不是 `ease-in`、纯 fade、居中缩放或某个毫秒值的绝对禁令。审查依据实际响应、可访问性、性能与一致性。

## 实现和验证

- 明确 transition 属性，避免 `transition: all` 意外动画布局或新增属性；有受控用途时以实际影响判断。
- 对快速重复触发、方向反转、取消和组件卸载检查跳变、队列积压、事件泄漏及状态错乱。
- 支持 `prefers-reduced-motion`，移除非必要空间运动并保留必要状态反馈。视频、持续动画需要相应停止/替代策略。
- 用真实浏览器检查改动的桌面/移动状态；必要时查看 computed style、慢放或逐帧定位 origin/时序问题。
- 手势和 sheet 检查真实触控或等效模拟；同时检查键盘、焦点、退出和滚动路径。
- 发现卡顿再检查 layout/paint、图层和媒体成本；不将 `will-change` 永久添加到所有组件。

输出具体问题、影响和建议。仅在实测显示阻碍操作、造成状态错误、可访问性缺陷或明显性能退化时阻断交付；偏好差异给可选建议，证据不足明确标注。
