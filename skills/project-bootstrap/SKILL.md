# Project Bootstrap

把用户目标转成可运行、可验证的最小项目，而不是先复制完整文档体系。

- 先读已有文件和用户约束；复用现有目录、语言、命令和贡献约定。
- 确认交付与最小验证路径；普通细节合理决定，只询问影响结果的缺失信息，并继续独立准备。
- README 写真实使用方式；需要持久代理约定时补短 AGENTS。长期跨阶段目标才补 spec/plan，实际发布才需要 changelog。
- 先确定最小架构和模块边界，再定义共享接口；用户已要求实现时继续打通主路径。有收益的独立模块主动委派，明确文件与运行资源归属。
- 源码、测试及生成物各归其位，自有临时文件用完即删；以真实集成结果验收，不能把初始化文档当成完成。
- 不自动创建新用户任务、原生 Goal、预算或自动化，不修改个人机器配置。

按需参考：

- `../../docs/project-AGENTS-template.md`：需要项目规则正文时。
- `../../docs/project-expansion-workflow.md`：初始化取舍不明确时。
- `../../docs/project-codex-config-template.md`：项目确实需要权限配置时。

验收以实际可运行结果和真实命令为准；未建立的环境或检查如实说明，不为满足模板编造验证。
