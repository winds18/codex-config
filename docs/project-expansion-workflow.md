# 项目初始化

初始化的目的是让项目能运行、能验证、能协作。先检查已有仓库，复用真实约定；空目录也只建立当前目标需要的结构。

## 最小流程

1. 从请求和已有文件确认交付、约束和验收。能合理判断的细节直接处理；影响结果的歧义尽早询问并继续独立准备。
2. 先确定最小架构、模块职责和依赖，再定义共享接口及验收场景；已有设计足够则复用。
3. 按文件和运行资源分配独立实现，主动并行推进并打通真实主路径，完成相关测试与集成验收。
4. README 记录真实命令；项目 AGENTS 只补特殊规则。长周期项目才增加 spec/plan，实际发布时再维护 changelog。
5. 清理自有临时文件与无关进程，交付实现及有效证据；成熟项目的普通功能直接沿用现有入口。

架构、契约、测试和目录规范以 [软件工程流程](../skills/autonomous-project-execution/references/software-engineering-workflow.md) 为详细入口。

可选模板：[项目规则](project-AGENTS-template.md)、[复杂计划](project-plan-template.md)、[权限配置](project-codex-config-template.md)。只读取实际需要的一份。

## 适配规则

- 新建文档内容必须有事实基础；不存在的启动或测试命令明确标记待建立，不能宣称已验证。
- 成熟仓库中的普通功能不重做 bootstrap；运行方式未改变时不为满足形式而改 README。
- `.codex/config.toml` 只放项目确实需要的设置；个人账号、凭证、模型可用性和插件不复制进仓库。
- worktree 初始化写成项目已有的环境入口；需要 Git hooks 时检查本工作树是否生效。
- 自动化或原生 Goal 只在用户请求时创建，不能由“需要持续实现”自行推断预算或定时调度。
