## 8. 线程治理规则

本项目默认采用：

- 主线程负责项目控制面
- 功能线程负责具体功能开发

主线程只负责：

- 维护 Mission / Constraints / Working Goal
- 维护项目级文档
- 派发功能线程
- 做阶段验收
- 做合并与归档决策

以下工作默认必须新开功能线程处理：

- 新功能开发
- bug 修复
- 重构
- 多轮测试修复
- 长日志调试
- 会持续产生中间噪音的实现任务

主线程允许的少量例外：

- 项目级文档同步
- 线程交接与调度
- 验收说明补充
- 合并前后的极小型收尾修订
- 不涉及真实功能开发的低噪音机械修正

本项目开发优先级默认是：

- 先打通框架、骨架或最小主路径
- 再完成主要功能板块
- 再补细节、边界情况和增强项
- 最后再做修饰、抛光和非关键优化

在主路径尚未打通前，不应优先陷入：

- 过早补齐大而全测试
- 过早扩写大量文档
- 长时间打磨局部细节
- 非关键区域过度重构

文档和测试必须服务推进，而不是抢占推进。

功能线程完成后，必须向主线程回报：

- 目标
- 实际完成内容
- 验证结果
- 变更范围
- 已知限制

验收通过后：

- 合并改动
- 归档该功能线程

默认在 `docs/plan.md` 中维护线程总表。

## 9. Goal 管理规则

本项目按以下层级管理目标：

- `Mission`：写在 `docs/spec.md`
- `Constraints`：写在本文件和 `docs/spec.md`
- `Working Goal`：写在 `docs/plan.md`
- `Stage Objective`：写在 `docs/plan.md`

允许调整：

- `Working Goal`
- `Stage Objective`

不允许静默调整：

- `Mission`
- 核心 `Constraints`

每次 goal 纠偏时，应在相关文档或执行总结中记录：

- 原目标
- 新目标
- 调整原因
- 对交付的影响

## 12. 提交策略

本项目默认分支模型：

- `main`：稳定主线，只接收已验证成果
- `feature/*`：新功能
- `fix/*`：缺陷修复
- `refactor/*`：重构
- `docs/*`：文档调整
- `chore/*`：维护事项
- `experiment/*`：实验分支，不直接合并到主线
- `release/*`：发布准备，仅在项目需要时启用
- `hotfix/*`：紧急修复，仅在项目需要时启用

分支规则：

- 一个功能线程默认对应一个工作分支或 worktree
- 一个分支只服务一个清晰目标
- 合并前必须完成相关验证
- 合并后归档功能线程，并清理临时分支或 worktree

默认提交时机：

- 一个阶段通过验证后
- 一个明确 bug 修复被确认后
- 一个高风险重构稳定后

默认不要提交：

- 未验证的半成品
- 纯试探性改动
- 明显会被马上推翻的临时代码

提交前整理顺序：

1. 查看 `git status` 与相关 diff
2. 确认本次提交边界
3. 只暂存同一目的下的相关改动
4. 运行相关验证或项目 guard
5. 同步关键文档
6. 再提交

建议提交信息风格：

```text
feat: 增加用户登录入口
fix: 修复启动失败问题
refactor: 收敛配置加载逻辑
docs: 更新部署说明
test: 补充核心流程验证
```

提交标题和 body 默认使用中文，`type` 可以保留英文约定。

如果项目需要版本号、emoji 或 `commit-msg` 校验，在这里明确写出。

如果项目没有发布版本要求，不要默认强制每次提交提升版本号。

## 15. 文档同步要求

长期维护的 `docs/*.md` 建议使用轻量文档信息表：

```markdown
## 文档信息

| 项目 | 内容 |
| --- | --- |
| 状态 | 生效中 |
| 最后更新 | YYYY-MM-DD |
| 适用范围 | 本项目 / 某模块 / 某阶段 |
| 关联入口 | AGENTS.md / README.md / docs/plan.md |
```

表头不用于制造审批流，只用于判断文档状态、适用范围和入口关系。

`AGENTS.md`、`README.md`、`CHANGELOG.md`、临时记录和自动生成文件不强制添加表头。

以下情况发生时，应同步更新文档：

- 项目目标变化
- 阶段顺序变化
- 运行方式变化
- 测试命令变化
- 关键架构决策变化
- 线程状态变化

至少同步以下文件：

- `README.md`
- `docs/spec.md`
- `docs/plan.md`
- `CHANGELOG.md`
