# Git 与交付

沿用目标项目的分支、语言和发布约定。没有既有约定时，采用短命工作分支、小而完整的检查点；不强制 release 分支或每次提交升版本。

## 提交与推送

- 提交前检查真实暂存 diff，只包含同一目的的改动；运行当前改动所需检查。
- 推送前核对目标与将发送的历史。secret 可能已从工作区删除但仍存在历史；扫描覆盖 merge 和新远程分支。
- 不重写用户改动、不借清理删除同伴文件；构建产物、缓存和临时文件按项目规则管理。
- 自建一次性文件、日志和临时目录用完即删；需保留的验收产物说明位置和用途。只清理确认属于本任务的内容，忽略规则或清洁检查提示都不构成删除他人文件的依据。
- 提交、推送、PR、部署是不同动作，依当前请求和已给授权执行。未授权外部动作先准备具体结果，不扩大授权。

## 本仓库 Git hooks

`bash scripts/install-git-hooks.sh` 为当前工作树安装 `core.hooksPath`。现有自定义 hook 配置不能静默覆盖；具体参数见脚本帮助。新 worktree 应确认配置作用域，而不是假设继承。

pre-commit 运行 guard；pre-push 先检查将推送历史，再运行 guard。Git hooks 是本地检查，可被其他客户端或 Git 参数跳过，不是服务器安全边界。重要远程仍需自己的保护和 CI。

清洁检查只读检查暂存噪音并提示根目录问题，不证明全部临时资源已清理；交付前另核对本任务的临时目录和进程。未暂存的他人临时内容不因本检查而被删除或阻断提交。

扫描范围是暂存/已跟踪文件、待推送提交的文件 blob 与敏感路径；新远程分支保守扫描可达历史。它不扫描 commit/tag 消息、子模块内部历史或所有凭证格式；指向非提交对象的标签会明确报错。超限文件会阻止扫描成功，不能视为已检查。

## 验证与发布

检查应对应实际暂存内容及集成状态，不靠“测试通过”字样。工作树验证与暂存快照不同或有未验证面时明确说明。发布前更新真实版本源并校验产物可追溯；不默认修改远程 tag。
